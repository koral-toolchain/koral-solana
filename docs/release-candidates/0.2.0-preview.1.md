# 0.2.0-preview.1 candidate

Status: preparation only; not a published release. The public v0.1.0-dev download
remains unchanged. These notes do not approve publication or identify a final
artifact. The promotion record must identify the reviewed main commit, successful
CI run, candidate artifact ID and SHA-256 before owner approval.

## Try a payment or SOL vault project locally

The proposed minor preview groups related work around a complete developer path:
create a project, build native SBF and verify actual behavior without a wallet.

```sh
koral init hello-payments --template payments
cd hello-payments
koral setup
koral check
koral build
koral test
```

Use `--template sol-vault` for the separate vault example, or omit --template for
the existing Counter. Follow [installation and SDK setup](../FIRST-PROJECT.md).
JDK 17 and the pinned Agave SBF SDK are required for compilation. Node 22.12+
and npm are additionally needed for local VM tests. setup explicitly downloads
pinned VM dependencies; build and test do not install them automatically.

## Changes since 0.1.0-dev

- Payment and SOL-vault templates select their matching fixed native test suites;
  explicit binaries can select --suite. Failed runs and rebuilds invalidate stale
  success reports. Reports cannot overwrite protected build/source files.
- External accounts support fixed owner/address, exact byte-size and explicit
  executable true/false constraints, checked before the selected body.
- Program-owned SOL vaults support authority-funded deposits and rent-preserving
  direct withdrawals with canonical PDA/authority and rollback checks.
- Source rejections include useful locations and readable reasons without internal
  exception traces for expected unsupported source.

## Compatibility and migration

This is an additive minor preview, with no increase to the required JDK, Kotlin,
Node, Gradle or SDK versions. Counter format-1 projects and explicit source/binary
commands retain their behavior. New payment/vault projects use format=2 and an
allowlisted test suite. Each suite expects its template's instructions, state and
seed contract; it is not an automatic test generator for arbitrary contracts.

The internal model writer now emits KOR7. The current reader accepts older
KOR4/KOR5/KOR6 inputs, but old compilers cannot read new KOR7 files. Regenerate
internal artifacts from original Kotlin source with the matching compiler instead
of mixing tool versions. No persisted account layout or seed migration is
introduced for existing contracts; vaults use their distinct declared contract.
The model and preview ABI remain experimental, rather than stable interchange
formats. See [the language contract](../LANGUAGE.md).

## Evidence and limits

Promotion requires all checks in [the release checklist](../RELEASING.md),
including the exact CI-produced TAR. Local or pull-request checks alone do not
approve an independently rebuilt or different revision's artifact. CI covers
Linux x64 JDK17/Node22 and JDK21/Node24; macOS arm64 evidence is local only.

Stored benchmark results remain historical measurements of their recorded
sources/tools. This packaging/version change makes no new compute-unit claim.
The vault comparison separates selected bump-search strata and preserves the
auxiliary baseline differences. See [vault comparison evidence](../../benchmarks/results/sol-vault/REPORT.md).

No arbitrary account-data decoding, SPL Token CPI, general PDA signing, full DEX,
security audit, general Kotlin support or mainnet deployment is provided. The
separate website worker still exposes its own deployed fixed examples; this
candidate does not update that worker. Original Koral materials remain proprietary
with all rights reserved, and third-party notices remain in the archive.

## Installation and recovery after promotion

A published release must supply the exact verified archive, SHA-256 sums and a
provenance record with source and CI identities. Check the checksum, extract to a
new directory and run doctor, setup and the example workflow above. Keep the old
installation separate; restore its PATH to roll back. Regenerate build/model
artifacts with the compiler you selected. Never overwrite an existing release tag
or published asset with different bytes.
