The release assets record the exact source, successful main CI, artifact identity

the qualification scope; release assets are the immutable provenance record.

## A usable path for your own contract

```sh
koral init my-program --template custom
cd my-program
koral setup
koral check
koral build
koral test
```

Edit the Kotlin and tests/program.test.mjs together. The bundled preview ABI
client handles named arguments/accounts, instruction data, canonical PDA, state
decoding and local VM transactions. Tests own their assertions. Reports describe
script completion, not inferred coverage or contract safety.

Fixed template mismatches now explain the custom workflow. Failed assertions
retain user file/line information; entry/imported syntax errors preserve native
source code frames without rerunning tests. Missing imports retain useful context.

## Compatibility and requirements

This is an additive minor development preview. Existing Counter format-1 projects,
format-2 payment/vault projects and explicit Counter binary commands remain supported.
The language/runtime, account layouts, KOR7 model and preview ABI schema are unchanged
in this cycle. No new CU claim follows from packaging or client improvements.

JDK17+, Node22.12+ with npm for tests, and Agave3.1.10/platform-tools1.52 remain
external prerequisites. Hosted CI verifies Linux x64 JDK17/Node22 and JDK21/Node24;
macOS arm64 evidence is local. Fresh Ubuntu24.04 x64 container evidence is emulated
on Apple Silicon, with fresh SDK downloads and no host cache mount.

The JavaScript consumer tools are bundled, not published to npm. There is no Maven
or Gradle plugin publication, RPC/wallet/deployment automation or general Kotlin
support. setup explicitly installs locked VM dependencies. User test scripts run
with normal local permissions; review unfamiliar scripts before execution.

## Known limits and next decision

The inventory demo verifies an owner-operated aggregate ledger from zero state,
not individual reservations or a production stock service. Generic initialize
still accepts all state fields without running Kotlin instruction guards. An
invalid inventory initial payload is accepted and only later operations reject
it. This is recorded as an unmet application requirement, not hidden as success.
The next selected proposal is opt-in zero-only initialization, with real SBF policy
and rollback tests; it is not implemented in this preview. Restricted pure helpers
and easier SDK onboarding follow it. See [ROADMAP.md](../ROADMAP.md).

Original Koral materials remain proprietary with all rights reserved. Third-party
notices are packaged. This preview is not an audit, stable language/ABI, universal
Solana support or mainnet release. The separately deployed website worker keeps
its existing fixed-example compiler image unless explicitly updated independently.

## Promotion and recovery

Promote the exact reviewed main-CI TAR without rebuilding, publish its checksum
and provenance, then verify anonymous public downloads. Keep old installations
separate; restore the old PATH and regenerate build artifacts with that compiler
to roll back. Never replace an existing version's tag or asset bytes.
